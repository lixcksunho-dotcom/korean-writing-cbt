# 행사 코드 운영 — 블로그 홍보 → 1개월 무료

두 서비스(kbspass·kptest)에 같은 구조로 들어가 있다.

## 흐름

1. 블로그에 홍보 글을 쓴다
2. 글 아래에 **진행 중인 행사 배너가 자동으로 뜬다** — 코드가 그 자리에 보인다
3. 읽은 사람이 `/subscribe`에서 코드를 넣는다
4. 이용권이 즉시 나간다(무료 발급, 0원)
5. 어드민 → **행사 코드**에서 몇 명이 받아 갔는지 본다

배너는 손으로 넣고 지우지 않는다. 행사가 끝나면 저절로 사라지고, 새 행사를 넣으면
저절로 뜬다 — 지난 행사 문구가 남아 사람을 헛걸음시키는 사고를 없애기 위해서다.

## 새 행사 여는 법 (1분)

`src/lib/promoCampaign.ts`의 `PROMO_CAMPAIGNS`에 한 줄 추가하고 배포한다.

```ts
{
  code: 'BLOG1001',          // 대문자·숫자만. O/0, I/1처럼 헷갈리는 글자는 피한다
  label: '10월 블로그 이벤트 · 1개월',
  days: 30,
  maxUses: 100,              // 선착순 인원
  startsAt: '2026-10-01T00:00:00+09:00',
  endsAt:   '2026-10-31T23:59:59+09:00',
},
```

**끝난 행사도 지우지 말 것.** 지우면 나중에 "이 코드가 뭐였는지"를 못 찾는다.
기간이 지나면 자동으로 '종료'가 되고 배너에서도 빠진다.

## 규칙(코드가 강제하는 것)

- **한 사람이 같은 코드를 두 번 못 쓴다** — `subscriptions.order_id`의 unique 제약이
  막는다. 화면 검사가 아니라 DB 제약이라 동시 요청도 통과 못 한다.
- **이미 이용권이 있으면 남은 기간 뒤에 이어 붙인다** — 겹쳐 주면 돈 낸 사람이 손해다.
- **매출에 섞이지 않는다** — 금액 0원으로 기록돼 `check:revenue`가 '무료 발급'으로 가른다.
  실제로 발급을 넣은 뒤에도 원장 대조가 '일치 ✓'로 유지되는 것을 확인했다.
- **기간 밖 코드·없는 코드는 각각 다른 안내로 거절된다** — 사람이 왜 안 되는지 안다.

## 확인

```bash
npm run check:promo     # 없는 코드 거절 · 발급 · 0원 기록 · 재사용 차단 · 건수
```

행사를 새로 열었으면 코드를 지정해 한 번 돌려 본다:

```bash
PROMO_CODE=BLOG1001 npm run check:promo
```
