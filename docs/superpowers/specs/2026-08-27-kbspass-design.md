# kbspass — KBS한국어능력시험 대비 사이트 설계

작성 2026-08-27

## 왜 만드는가

사업자를 가르기 위해서다. kbspass는 **처음부터 어머니 사업자**로 열고, 실글패스(kptest.cloud)는
11월 말에 같은 사업자로 넘긴다. 두 사이트가 한 코드·한 결제·한 DB를 쓰면 그 분리가 성립하지 않는다.

부수 효과로 브랜드와 검색 노출도 갈린다. 다만 그것은 목적이 아니라 결과다.

## 범위

**만드는 것**: KBS한국어능력시험 대비 CBT 사이트 한 벌. 실글패스와 같은 기능(모의고사·AI 채점·
이용권 결제·관리자)을 갖되, 저장소·DB·결제·도메인·사업자가 전부 분리된다.

**만들지 않는 것**: 두 사이트를 잇는 계정 연동, 공통 로그인, 통합 관리자. 사업자가 다르므로
개인정보 처리자도 다르다 — 잇는 순간 분리한 이유가 사라진다.

## 구조

저장소를 **복제**해서 시작한다. 백지에서 시작하면 결제·이용권·AI 채점·관리자·검사 스크립트를
다시 만들어야 하는데 몇 주 분량이고, 그 과정에서 이미 잡아 둔 사고(결제창이 안 열리던 것,
환불 뒤 이용권이 남던 것)를 다시 밟게 된다.

```
kbspass 저장소 (kptest 복제)
  ├─ 남긴다  시험 엔진 · 결제 · 이용권 · AI 채점 · 관리자 · 검사 스크립트 전부
  ├─ 지운다  실용글쓰기 문항 467개(16회차) · 블로그 79편 · silyong 프로그램 설정
  └─ 바꾼다  브랜드 문자열(45개 파일 96군데) · businessInfo · 도메인 · 결제 키 · DB 접속
```

### 새로 준비해야 하는 것 (사람 손)

| 무엇 | 누가 | 비고 |
| --- | --- | --- |
| 어머니 사업자 + 통신판매업 | 사장님 | **준비 완료** |
| Supabase 프로젝트 | 사장님 | 새 프로젝트. 마이그레이션은 SQL Editor에서 실행 |
| Vercel 프로젝트 | 사장님 | 새 저장소 연결 |
| 도메인 `kbspass.*` | 사장님 | 확장자 미정 |
| 포트원 상점(어머니 사업자) | 사장님 | 이니시스·카카오페이 심사 — **카카오페이는 시간이 걸린다(실글패스 사례)** |
| Anthropic API 키 | 사장님 | 실글패스와 나눠 쓰지 않는다(사업자가 다르면 비용 귀속도 다르다) |

### 데이터

KBS 문항 **300개(2025년 1·2·3회, 각 100문항)** 를 새 Supabase로 복사한다. 원본은 그대로 둔다.
계정·결제·풀이 기록은 옮기지 않는다 — 실글패스 고객의 데이터이고, 처리자가 다르다.

## 콘텐츠 현실 (열린 결정)

지금 KBS는 **3회차뿐**이다. 무료 1회차 정책이면 유료로 열리는 것이 2회차다. 실글패스가 16회차인
것과 비교되면 5,500원은 환불 사유가 된다.

두 갈래가 있고 아직 정하지 않았다.

- **회차를 채우고 연다** — 출시가 늦지만 첫인상이 온전하다. 최소 6~8회차를 권한다.
- **먼저 열고 채운다** — 초반에는 무료로만 열고(결제 버튼 없이) 회차가 쌓이면 유료화한다.
  검색 노출은 도메인 나이를 먹으므로 일찍 여는 편이 유리하다.

**권고: 먼저 열되 결제는 나중에.** 도메인·색인은 시간이 필요하고, 콘텐츠가 얇은 상태로
돈을 받는 것이 가장 나쁘다. 결제 계약(포트원 심사)도 그 사이에 진행하면 된다.

## 두 저장소가 갈라지는 문제

코드가 두 벌이면 결제 버그를 두 번 고쳐야 한다. 없앨 수는 없고, 줄인다.

- **공통 파일 목록을 두 저장소 README에 명시한다.** 결제·이용권·환불 회수·알림·검사 스크립트가
  대상이다. 목록에 있는 파일을 고치면 반대쪽에도 반영하는 것을 규칙으로 한다.
- **검사 스크립트(`check:*`)를 그대로 복제한다.** 한쪽에서 잡히는 결함은 다른 쪽에서도 잡힌다.
  특히 `check:methods`(열리지 않는 결제 버튼)·`check:revoke`(환불 회수)·`check:alerts`(알림 도달)는
  실제 사고에서 나온 것들이다.
- 시간이 지나 갈라지는 것 자체는 받아들인다. 완전 동기화를 목표로 삼으면 둘 다 못 고친다.

## 실글패스 11월 이전과의 관계

kbspass가 먼저다. 어머니 사업자로 **포트원 계약을 한 번 통과시켜 두면**, 11월에 실글패스를
넘길 때 같은 상점에 도메인·채널을 추가하는 방식으로 훨씬 간단해질 수 있다(포트원 정책 확인 필요).

실글패스 이전 자체는 별도 문서로 다룬다. 요점만: 결제 가맹점 재계약(CID·채널키 전부 새로),
`businessInfo.ts` 교체, 정산 계좌, 약관·개인정보·환불정책 표시.

## 완료 기준

1. `kbspass.*` 도메인으로 사이트가 뜨고, 브랜드에 '실글패스'가 한 군데도 남지 않는다
2. KBS 3회차를 비회원이 무료로 풀고 결과를 본다
3. 관리자 화면이 열리고 알림 채널이 '정상'으로 뜬다
4. 사업자 정보(어머니)가 푸터·약관·개인정보·환불정책에 정확히 표시된다
5. 검사 스크립트가 전부 통과한다
6. (결제를 여는 시점) 카카오페이·카드로 실결제 1건이 `verify:payment` 7/7을 통과한다

## 하지 않기로 한 것

- 두 사이트 계정 연동 — 사업자 분리의 목적에 반한다
- 모노레포 — 사장님이 별도 코드를 선택했다. 유지보수 중복은 위 규칙으로 관리한다
- 실글패스 데이터 이관 — 고객 데이터는 처리자가 바뀌면 안 된다
